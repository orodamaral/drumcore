Guia rápido

Gravando o firmware na placa

O firmware é construído com PlatformIO (não Arduino IDE), pra manter as dependências versionadas junto com o código. A placa alvo é um ESP32-S3 (módulo real usado: ESP32-S3-N16R8, 16MB flash + 8MB PSRAM octal).

Pré-requisitos

Qualquer um dos dois caminhos abaixo funciona — o segundo é mais rápido se você só quer compilar/gravar sem abrir um editor.

🧩

VS Code + extensão PlatformIO

Instale a extensão "PlatformIO IDE" na Marketplace do VS Code. Ela já traz o CLI embutido e integra com os botões de build/upload.

⌨️

PlatformIO CLI standalone

Com Python instalado: pip install platformio. Os comandos deste guia (pio run ...) funcionam direto no terminal depois disso.

Passo a passo

  1. Clone o repositório

    Pega o código-fonte completo (firmware, app desktop, hardware, documentação).

    git clone https://github.com/orodamaral/drumcore.git
cd drumcore/firmware

  2. Abra a pasta firmware/

    No VS Code: File → Open Folder, aponte pra firmware/ — o PlatformIO detecta o platformio.ini automaticamente. A biblioteca de sensing vendorizada em firmware/lib/ é carregada junto, sem passo extra.

  3. Conecte a placa via USB-C

    Use um cabo USB-C que transmita dados (alguns cabos são só de energia). O sistema deve reconhecer uma porta serial nova (ex: COM5 no Windows, /dev/ttyUSB0//dev/ttyACM0 no Linux).

  4. Compile

    Só pra conferir que fecha sem erro antes de gravar:

    pio run -e esp32-s3-devkitc-1

  5. Grave na placa

    Compila de novo (se algo mudou) e já envia pro ESP32-S3 via USB:

    pio run -e esp32-s3-devkitc-1 -t upload
    💡 Se a porta certa não for detectada automaticamente, especifique com --upload-port COM5 (troque pela porta real da sua máquina).

  6. Acompanhe pelo monitor serial (opcional)

    O firmware fala NDJSON a 115200 baud com o app desktop, mas também dá pra ver os logs direto:

    pio device monitor -b 115200

Ambientes de build disponíveis

firmware/platformio.ini define um ambiente principal e alguns ambientes de teste isolado — cada um compila só um arquivo .cpp (com seu próprio setup()/loop()), úteis pra validar uma peça de hardware isoladamente sem o firmware inteiro no meio.

esp32-s3-devkitc-1

Firmware principal — MUX, tela, encoder, USB-MIDI, BLE-MIDI, EEPROM, protocolo serial. É o que vai pro módulo de verdade.

pio run -e esp32-s3-devkitc-1 -t upload
display_test

Só a tela TFT (logo de boot) — isolado de MUX/encoder/USB/BLE/EEPROM.

pio run -e display_test -t upload
test_pads

Regressão do array de 32 pads da biblioteca de sensing — sem tela/MUX/USB/BLE.

pio run -e test_pads -t upload
test_rgbled

LED RGB embutido (GPIO48) — teste mínimo de saúde do build/gravação.

pio run -e test_rgbled -t upload
test_hall

Leitura direta do sensor hall (SS49E) no GPIO17, valor bruto do ADC na tela + Serial.

pio run -e test_hall -t upload

⚠️ Todos usam a mesma placa serigrafada esp32-s3-devkitc-1 do PlatformIO, mas com overrides pro módulo real (N16R8 — 16MB flash, PSRAM octal). Se você usar outra variante do ESP32-S3, confira board_build.*/board_upload.* em platformio.ini antes de gravar.

Dúvidas sobre o porquê de cada escolha de build (USB mode, PSRAM, link do TinyUSB)? Ver docs/01-decisoes-arquiteturais.md no repositório — cada decisão de infraestrutura tem o racional completo registrado.
